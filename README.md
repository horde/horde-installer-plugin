# Horde Installer Plugin for composer

This plugin allows composer-based installation of the Horde 6 Framework and application

## Usage

Require the plugin in your base project to properly install horde applications beneath it.
Whenever you do manual changes after installation, run command

```
composer horde:reconfigure
```

If you want to start from scratch, go to var/config/horde/registry.d dir and delete the 00-horde.php file.

### Web Server DocumentRoot

Point your web server's document root to the web/ dir below your base project.

The current layout is transitional and convoluted by the fact that during much of Horde 6' development, backward compatibility with the old layout was kept.
Generally the files really live under /vendor/horde/* and only the relevant parts are linked to web dir to make everything work.
Eventually application design will change and require much less installation magic to work correctly.

### Default Application URLs

Default application URLs are on the same level below web/
i.e. "horde" portal and webroot app is under /web/horde. If your webroot is "https://server.org", then "horde" is under "https://server.org/horde"
i.e. "nag" tasks is under /web/nag. If your webroot is "https://server.org", then "nag" is under "https://server.org/nag"
i.e. "imp" webmail is under /web/imp. If your webroot is "https://server.org", then "imp" is under "https://server.org/imp"

This is different from Horde 5 which had all applications installed below the horde base application.

### Default asset URLs

The php-writable, web-readable static asset directory is under web/static.
This is where minified js and theme files are cached for the browsers to fetch them.

Default javascript URL is web/js/$app.
i.e. Javascript files for horde base are placed under web/js/horde. Javascript files from libraries like horde/core are also installed under web/js/horde.
i.e. Javascript files for kronolith calendar are installed under web/js/kronolith

Themes are placed under web/themes/$app/$theme.
i.e. The default theme files for the global (horde app) portion of the default theme is under web/themes/horde/default
i.e. The default theme files for the kronolith specific portion of a "materialui" theme would be under web/themes/kronolith/materialui

This is different from Horde 5 which had all assets under horde/themes, horde/js, horde/$app/themes, horde/$app/js, horde/static
Applications generally need access to the filesystem and url locations of the horde base pendants to work correctly.

### API endpoints and forwarding

The index.php of the default base project horde/bundle will forward calls for the web root to /horde/ unless the conf.php file is missing.

The actual API endpoint file for the JSON-RPC and webdav APIs is under web/horde/rpc/index.php and web/horde/rpc.php. Both are mostly equivalent.
The webroot contains a .htaccess file to forward requests for $DOCUMENT_ROOT/rpc/ and $DOCUMENT_ROOT/rpc.php to $DOCUMENT_ROOT/horde/rpc/ and $DOCUMENT_ROOT/horde/rpc.php
You need to mimick this configuration when using other web servers such as nginx or make your users migrate to the new endpoint locations.
The actual API endpoint file for the URL router is under web/horde/rampage.php.

The webroot contains a .htaccess file to forward requests for $DOCUMENT_ROOT/rampage.php and pretty much everything except rpc and login to $DOCUMENT_ROOT/horde/rampage.php
This works well for standard deployments but might break when using separate webroots for applications which are not prepared for this scenario.

Upcoming versions will probably integrate index.php of each application and rampage.php into a single endpoint which just works.

## Separate Subdomain Webroot configuration

You can expose individual apps directly under a separate subdomain of the same domain. 
Completely distinct domains per app are currently not supported by the login mechanism's cookie generation.

Starting with horde/horde-installer-plugin v2.7.0 we will introduce a simpler mechanism.
For now you need to manually add config files for each app to var/config/horde/registry.d/ 

The following configuration file would place the nag tasks app under https://tasks.mydomain.org and the passwd app under https://passwords.mydomain.org.


<?php
/**
 * AUTOGENERATED ONLY IF ABSENT
 * Edit this file to match your needs
 * To redo, delete file and run `composer horde-reconfigure`
 */
$deployment_webroot = 'http://horde.dev.localhost:5080';
$deployment_fileroot = '/var/www/horde-dev/web';
$app_fileroot = '/var/www/horde-dev/web/horde';
$app_webroot = '/horde';
$canonical_webroots = [
    'horde' => 'http://horde.dev.localhost:5080/horde',
    'js' => 'http://horde.dev.localhost:5080/js',
    'static' => 'http://horde.dev.localhost:5080/static',
    'themes' => 'http://horde.dev.localhost:5080/themes',
    'nag' => 'http://tasks.dev.localhost:5080/'


$this->applications['horde']['fileroot'] = $app_fileroot;
$this->applications['horde']['webroot'] = $canonical_webroots['horde'] ?? $app_webroot;
$this->applications['horde']['jsfs'] = $deployment_fileroot . '/js/horde/';
$this->applications['horde']['jsuri'] = $canonical_webroots['js'] .'/horde' ?? $deployment_webroot . 'js/horde/';
$this->applications['horde']['staticfs'] = $deployment_fileroot . '/static';
$this->applications['horde']['staticuri'] = $canonical_webroots['static'] ?? $deployment_webroot . 'static';
$this->applications['horde']['themesfs'] = $deployment_fileroot . '/themes/horde/';
$this->applications['horde']['themesuri'] = $canonical_webroots['themes'] .'/horde' ?? $deployment_webroot . 'themes/horde/'



Now also edit the 00-horde.php file
Old:
```
<?php
$deployment_webroot = '/';
$deployment_fileroot = '/var/www/horde-dev/web';
$app_fileroot = '/var/www/horde-dev/web/horde';
$app_webroot = '/horde';
```
New:
```
<?php
/**
 * AUTOGENERATED ONLY IF ABSENT
 * Edit this file to match your needs
 * To redo, delete file and run `composer horde-reconfigure`
 */
$deployment_webroot = 'https://groupware.mydomain.org';
$deployment_fileroot = '/var/www/horde-dev/web';
$app_fileroot = '/var/www/horde-dev/web/horde';
$app_webroot = '/horde';
```

Please use the protocol (http or https), domain and optionally port the user actually sees, not the ones from any intermediate reverse proxy



## Linux

The plugin will create a var/ structure and a web/ structure in the root project.
web/ will contain symlinks of applications, javascript and themes content.
Supporting configuration for registry and applications is auto-configured.
The composer autoloader is injected into the bootstrap process.

## Windows

Windows support is preliminary. Symlinks are replaced with copies. This means you will need to run the command 
```composer horde-reconfigure ```
much more often and any wizard-generated content is overwritten with the contents of your var/config directory on any update.
Windows support is not well-tested. Patches and issues welcome.
